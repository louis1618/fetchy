# Fetchy 1.0.8 구현 계획

## 범위와 기존 경로

- 선택 기능: 로그인 유효 여부 확인, 실패 원인/진단 공유, 선택 자막 SRT/VTT 저장, 앱 내 영상/오디오 재생, 오디오 태그/커버, 기존 파일의 저장 위치 이전.
- `Engine.kt`의 분석·다운로드·FFmpeg, `Cookies.kt`의 암호화 저장소, `Storage.kt`의 SAF·복사 검증·복구 저널, `Runtime.kt`의 작업/백그라운드 실행을 재사용한다. 새 서버와 미디어 라이브러리를 추가하지 않는다.
- Flutter의 기존 색상·카드·하단 시트를 유지하고 필요한 선택/상태만 추가한다. Morit과 기존 쿠키·파일·설정은 보존한다.

## 구현 순서

1. **자동 화질:** 추가 화질 검색 버튼을 제거한다. 실제 형식 목록에서 설정 화질 이하의 최고 해상도를 자동 선택하고 최고 설정은 실제 최대 해상도를 선택한다. 범위 내 화질이 없으면 제공되는 화질을 표시한다. Instagram의 빠른 원본 응답은 설정에 따른 엔진 자동 선택을 제공해 미리보기 단계에서 두 번째 분석을 기다리지 않는다. 실제 저장 해상도는 검증 정보로 기록한다.
2. **로그인 확인:** 설정의 플랫폼 메뉴에서 실행한다. 쿠키의 만료/변경을 반영하고, 해당 플랫폼의 첫 번째 당사자 인증 응답만 사용한다. 확인된 로그인·로그아웃·만료·확인 불가를 구분한다. 공개 페이지의 HTTP 200이나 쿠키 존재만으로 로그인 성공을 표시하지 않는다. 확인 요청을 분석의 필수 단계로 만들지 않는다.
3. **실패/진단:** 공통 오류 코드·해결 안내를 분석/다운로드/저장에 적용한다. 사용자가 선택해 앱/Android/엔진/네트워크 설정/오류 분류만 JSON으로 공유한다. 쿠키, 계정, 원본 URL, 제목, 헤더, 원시 로그는 내보내지 않는다.
4. **자막:** 분석에서 실제 제공되는 수동/자동 자막 언어를 보존한다. 언어와 SRT/VTT를 선택하고 해당 자산의 자막만 다운로드·변환·검증한 뒤 미디어와 같은 위치에 저장한다. 부가 파일 실패는 본 미디어와 구분해 표시한다. 완료 기록/복구는 안정된 파일 ID를 사용한다.
5. **오디오 정보:** 소스의 제목·아티스트·앨범 정보를 보존하고 오디오 탭에서 수정 가능하게 한다. FFmpeg의 스트림 복사로 태그를 넣고 지원 컨테이너에 커버를 추가한다. 없는 정보는 만들지 않는다. 커버 요청은 크기/경로를 검사하고 실패를 표시한다.
6. **앱 내 재생:** Android 기본 MediaPlayer로 저장된 Content URI만 재생한다. 재생/일시정지/탐색·음성 포커스·화면 수명주기 처리를 제공한다. 지원되지 않는 형식에는 시스템 앱 열기를 제공한다. 이미지 상세는 유지한다.
7. **저장 위치 이전:** 위치만 변경하거나 기존 자료도 이전하는 선택을 제공한다. 진행 중 다운로드가 있으면 이전을 제한한다. 현재 루트의 기록된 최상위 폴더 전체 내용과 루트 직속 파일을 대상으로 하며 충돌은 새 이름으로 보존한다. 기존 전송/검증 저널을 사용하고 원본 삭제는 검증 후 수행한다. 중단/실패를 기록하고 재시작/재시도로 이어서 처리한다. 기존 위치 권한과 찾을 수 없는 자료의 기록은 보존한다.

## 영향과 검증

- 채널 명령/설정/스냅샷, 분석 자산·작업·파일의 선택적 JSON 필드, 오류 안내, 설정·공유 시트·파일 상세, Manifest의 재생 Activity/진단 FileProvider를 함께 갱신한다. DB와 기존 레코드 ID는 유지한다.
- Flutter 정적 분석·위젯, JVM 오류/선택/개인정보 검사, Android 실제 저장·태그/커버·자막·재생·이전/중단 복구, 기존 다운로드·계층·삭제 회귀를 검사한다. 실제 인증된 계정이 없는 항목은 모의 응답 검사와 구분한다.
- 연결된 Android 12 실기기를 사용하고 에뮬레이터는 실행하지 않는다. build-safe RAM 6GiB/swap 512MiB 제한으로 빌드를 직렬 실행한다. 두 ABI의 설치 APK와 검증 기록을 제공한다.
- 플랫폼 응답 시간은 외부 네트워크에 영향을 받는다. 빠른 미리보기와 자동 선택의 시간을 따로 측정하며 모든 링크가 정해진 초 안에 끝난다고 보장하지 않는다.

## 구현 중 확인한 원인

- 임베드 숫자 PK와 yt-dlp shortcode ID 불일치로 Instagram 자동 화질 확인이 원본 대체로 끝나던 경로를 수정했습니다.
- 기본 제공자가 비어 있지 않은 폴더 삭제를 거부하므로, 검증된 복사의 원본 내용을 항목별로 정리하고 삭제 단계·대상 지문도 저널에 보존합니다.
- 자막 게시 실패 후 완료 기록/캐시 정리가 복구용 원본을 지우지 않게 했습니다. 언어·연결 ID도 게시 저널에 넣습니다.
- 실제 터치 탐색 테스트는 SOURCE_TOUCHSCREEN 이벤트를 사용하고, 지원 Android의 정확한 탐색·영상 첫 프레임 표시를 확인합니다.
- debug/release의 Kotlin 내부 메서드 이름을 컴파일 작업에서 고정해 최종 설치 APK로 네이티브 검사를 수행합니다.
- 오디오 태그 설정을 껐을 때 커버 설정도 무시하던 호출 조건을 수정하고 두 설정을 독립적으로 검사합니다.
