# X 인증 다운로드와 저장 날짜

- 제공한 X 링크는 연결된 Android 기기에서 `No supported original media formats`로 재현된다. 기존 공개 분석 우선 순서와 WebView 쿠키의 host-only 내보내기를 조사한다. 사용자 쿠키·기록은 유지하며 쿠키 값·비공개 원본 URL은 로그에 출력하지 않는다.
- 변경 범위는 `Cookies.kt`의 X API 쿠키 전달, `Engine.kt`의 인증 분석 순서·빈 공개 결과 대체, 관련 원본 선택/캐시 검사다. 외부 보조 분석 서비스에 쿠키를 전달하지 않는다.
- 저장 날짜는 `fileDate = download | source`로 설정한다. 기본은 현재 저장 시각이며 원본 게시 시각이 없으면 현재 시각을 사용한다. 원본 날짜와 선택 날짜를 구분해 보존한다.
- `Engine`에서 실제 timestamp/upload_date를 보존하고 `Runtime`에서 작업 설정으로 날짜를 선택한다. 날짜 파일명, 게시 저널, 파일 상세, 실제 파일 수정 시각과 가능한 MediaStore 날짜에 같은 값을 적용한다. 중복 건너뛰기는 기존 파일 날짜를 변경하지 않는다.
- 클라우드 등 날짜 변경을 지원하지 않는 저장 제공자는 파일을 보존하고 변경 불가를 기록한다. 다운로드 이력의 실행/완료 시각은 별도로 유지한다.
- 검사: 기존 설치의 쿠키 경로, 제공한 링크의 영상·오디오 실제 다운로드/저장, 공개 링크 회귀, 원본/현재/누락 날짜·파일/갤러리 날짜·게시 복구, Flutter 설정/상세, JVM과 Android 빌드. 에뮬레이터 대신 연결된 기기를 사용한다.

## 확인한 원인과 처리

- 실제 저장소에서 rootSession=true / apiSession=false를 확인했다. 기존 encrypted vault를 변경하지 않고 임시 Netscape 파일에 X API용 로그인 쿠키 행을 보완했다.
- 인증 후 X의 HTTP MP4는 코덱 정보가 생략되어도 실제 H.264/AAC 두 스트림을 포함했다. acodec=none일 때만 별도 오디오 병합을 선택한다. yt-dlp는 병합이 필요 없으면 merge-output-format을 무시하므로, 기존 병합 선택도 실제 영상 컨테이너를 받아 최종 설정 형식으로 처리한다. 자산·형식 ID와 스트림/무결성 검사는 유지한다.
- Android 12 실기기는 파일 수정 시각 변경을 허용했지만 MediaStore 행 날짜 갱신은 SecurityException으로 거부했다. 파일 시각과 갤러리 갱신 가능 여부를 따로 기록하고 설정에 차이를 안내한다. 원본 촬영 메타데이터는 유지한다.
